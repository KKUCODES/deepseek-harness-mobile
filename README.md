# DSH Mobile 手机端

## Git 仓库边界

本目录是独立 Git 仓库，默认分支为 `main`；电脑插件在相邻 `../plugin` 目录使用另一个仓库。初始化仅创建本地提交，远端由用户后续分别创建并关联。

仓库保存手机端源码、Android 工程与 Gradle wrapper、测试和夹具、依赖锁文件及文档。依赖目录、构建产物、APK、下载工具、联调数据、环境配置及本机签名文件不纳入版本管理，已有本地文件保持原位。验收文档引用的本地截图、日志和安装包不会随仓库分发，需在相应环境重新生成。

当前构建仍从相邻 `../deepseek-harness` 读取上游源码，部分联调依赖相邻插件及后端；跨项目文档链接也沿用现有目录布局。独立仓库不等于已支持单独克隆构建，本次不调整依赖交付方式。

仓库初始化任务：[KKC-22](https://linear.app/kkcodes/issue/KKC-22)。

## 当前交付

DSHM 是**以聊天为核心、连接电脑端 DSH 的移动客户端**，让用户离开电脑后仍能继续工作。普通聊天提供基础能力；连接 DSH 后，同一套聊天界面承接电脑会话、执行进展、结果、模型切换与审批。手机负责随身沟通与决策，电脑 DSH 执行任务，公网中转只负责连接与传输。此为产品定位，功能验收状态见下方记录。

首版范围已于2026-10-03确认：不提供手机访问电脑localhost网站，后续由[KKC-21](https://linear.app/kkcodes/issue/KKC-21)评估；文件预览、HTML文件预览和只读命令输出保留。详见[当前范围](./docs/integration/completion-audit.md)。历史记录中的网站转发待定状态以此决定为准。

已确认首版范围通过本地验收；使用与更新从[验收版交付说明](./docs/integration/local-delivery.md)进入，包含APK、配套插件/网关和电脑兼容补丁边界。当前为debug安装包；可执行`node scripts/check-delivery-artifacts.mjs`核对APK页面及插件运行文件是否与本地产物一致。当前状态以[验收表](./docs/integration/completion-audit.md)为准，下方旧专项中的待验描述保留其当时的版本与范围，不覆盖现行结论。

电脑返回的较早记录无法与当前历史衔接时，手机保留原内容和加载入口，提示手动重试，不把断层当作正常起点。两个历史入口共用[分页边界检查](./docs/integration/remote-current.md#历史断层保留重试2026-09-25)；错误页经过隔离回放验证，正常完整分页已在新版MuMu通过。

使用中断线时保留已加载的聊天、阅读位置和后台输出，并显示离线状态及最后同步时间；本机草稿仍可编辑，发送和审批等待重新核验连接。首次进入就连接失败时显示连接页，普通聊天独立可用；主动断开或授权失效会退出 Remote 页面。中继断线与恢复已通过 MuMu 验证，详见[当前记录](./docs/integration/remote-current.md)。

电脑 DSH 单独重启时也会重新核验后台任务能力。电脑不再保留的旧任务不能继续读取，手机保留已读内容并提示任务已变化；重连后新建任务可正常查看实时输出。此边界已在保持网关运行的 MuMu 测试中验证，不代表运行中会话回收或设备撤销的全部异常已通过。

页面设计已获确认，普通聊天功能验收已完成，见[当前实现与证据](./docs/integration/ordinary-current.md)及[全部接入任务](./docs/integration/README.md)。文案规则见[页面文案约定](./docs/design/ordinary-preview/copy-guidelines.md)。

使用 Node.js 24，在本目录执行：

```text
npm ci --ignore-scripts --legacy-peer-deps
npm run build:web
npm test
npm run verify:web
npm run serve
```

`verify:web` 回归独立诊断页，使用本机 Microsoft Edge 和临时 loopback 端口。`serve` 提供正式普通聊天 `http://127.0.0.1:4399/mobile.html` 和诊断页 `http://127.0.0.1:4399/`；浏览器不能调用 Android 原生模型桥。构建需保留旁边只读的 `../deepseek-harness` 基线检出。产物在 `dist/`，检查结果与截图在 `artifacts/`。

## Android 载体

Remote 列表支持标题和聊天内容搜索，显示命中摘要、加载/失败重试与结果上限提示，并保留工作区和归档筛选。正文搜索依赖电脑启用 DSH 的全文索引；上游 Web 默认关闭时手机明确提示，标题搜索仍可使用。启用配置与本地验收见[搜索说明](./docs/integration/remote-current.md#列表搜索与电脑索引2026-09-24)。

可在 Android 系统分享菜单中把完整配对链接分享给 DSHM，也支持 `dshm://pair?server=<编码后的服务器根地址>#key=<一次性key>` App 链接。打开后显示本机确认页，由用户点击“继续配对”，仍需电脑核对指纹并批准；已有绑定不会被外部链接覆盖。普通 HTTP/HTTPS 链接保留手动粘贴方式，不接管任意网站。电脑插件 0.1.19 可生成 App 链接及对应二维码，二维码由电脑本地生成。未绑定页新增“扫描二维码”和“从图片识别”，识别后只填入确认页；图片在手机本地读取，上限 8 MiB。MuMu 已验证图片识别及相机打开/取消，实际相机识别和权限拒绝仍未验证。当前系统入口验证范围见[记录](./docs/integration/remote-current.md#系统分享与-app-配对链接2026-09-24)。

`android/` 使用 Kotlin + WebView；APK 默认入口为正式普通聊天页，完整应用仍在开发与验收。保留原应用 ID 和来源，覆盖安装可继续使用原有 Key 和历史。使用 JDK 17、Gradle 8.9、AGP 8.7.3 和 Android SDK 35；设置本进程 `JAVA_HOME`/`ANDROID_HOME` 后，先构建 Web，再在 `android/` 执行 `./gradlew.bat :app:assembleDebug :app:lintDebug`。网页只加载 APK 本地资源；原生普通聊天桥仅允许主框架访问固定 DeepSeek HTTPS 端点，不向网页返回 Key。

debug 验证 APK 输出为 `android/app/build/outputs/apk/debug/app-debug.apk`，已验签并安装到用户启动的 MuMu；本地构建产物不提交。Android 功能回归复用 Web 检查脚本：通过 ADB 连接设备后，设置 `DSHM_ANDROID_SERIAL` 为 `adb devices` 的目标序列号，再运行 `npm run verify:web`。脚本只操作 `dev.dshmobile.validation`，会强制结束并重启该验证 App，不清除数据。

键盘排查可在设置同一 `DSHM_ANDROID_SERIAL` 后运行 `node scripts/diagnose-ime.mjs`。脚本对比 WebView 与 debug 包内原生 EditText，重启本验证 App、输出窗口几何及截图，结束后返回验证页；不修改默认输入法。当前 MuMu 在两种输入框下均报告键盘已显示但窗口高度为 0，诊断返回非零，真实软键盘验收仍未通过。详见[诊断记录](./docs/plugin-validation/results.md#真实软键盘环境诊断)。

打开 DSHM 后点击「配置 DeepSeek Key」，在原生窗口填写并保存；不要把 Key 发到聊天或写入网页配置。已有 Key 的入口在设置 → 普通聊天。可选择 Flash / Pro 和深度思考，发送、停止、搜索、编辑分支及保存下一条草稿。输入 `/总` 或 `/translate` 使用原输入插件；插件卸载后仍可直接编辑。支持系统选择的图片和 UTF-8 文本，图片理解需 Flash；普通聊天不执行 Agent。上下文只含已完成的轮次，并有条数/大小限制。设置 → 本地数据支持版本化备份，凭据不导出；卸载或清除 App 数据仍会丢失未备份历史。

侧边栏「Remote」打开独立环境。领取电脑端的一次性链接，经电脑核对指纹批准后连接；普通聊天 Key 不会传给 Remote。需要桌面插件 0.1.9 及更新后的 transport 2 网关，管理电脑插件需要电脑单独授权。当前只显示 DSHM 自己的页面，复用上游会话数据服务，不挂载电脑顶层界面。新版已在 MuMu 通过真实历史、文本续聊、系统选择文件上传、提问、队列编辑/取消、已有工作区新聊天、重命名、归档恢复和分支。聊天文件链接与工具文件按钮可预览电脑当前文本、图片、PDF、HTML 和 Office，Markdown 支持阅读/源码切换，文件窗口可全屏；文本全文预览上限 2 MiB，图片字节上限 16 MiB，PDF 上限 32 MiB。PDF 使用本地后台线程渲染并提供文字选择，关闭释放资源。下载和分享都重新读取电脑最新完整文件，上限 256 MiB；下载通过 Android 系统窗口保存，分享交给手机系统分享面板，由用户选择接收 App。准备期间支持取消和断线清理，重连不自动恢复；已交付给接收 App 的文件无法撤回。HTML 在独立沙箱中运行，支持直接引用的本地经典脚本和样式；不能访问聊天、手机文件或网络，不支持模块依赖图和 CSS 嵌套资源。文档与依赖合计上限 32 MiB，关闭释放资源。Office 支持 doc/docx、xls/xlsx、ppt/pptx，使用电脑 DSH 的转换服务，手机显示转换后的 PDF（上限 32 MiB）；缺少字体会提示，下载/分享仍提供原始文件。插件局部界面和高级操作尚未完成。旧客户端验证记录不代替新版验收，详见[当前实现与完整矩阵](./docs/integration/remote-current.md)及[隔离边界](./docs/plugin-validation/remote-native.md)。

用户已将性能验收调整为 FCP/LCP/CLS/TBT 等合理区间，不再要求目标真机或严格原生基准。运行 `npm run measure:page` 取得独立 Edge 中的 Lighthouse 三次对照；设置 `DSHM_ANDROID_SERIAL` 后运行 `node scripts/measure-android-page.mjs` 取得 MuMu 页面指标。两者不能冒充真机结果，模型网络延迟也不算页面启动耗时。详见[验收计划](./docs/plugin-validation/validation-plan.md)和[当前结果](./docs/plugin-validation/results.md)。

正式入口真实 API 验证：设置 `DSHM_ANDROID_SERIAL`、`DSHM_RUN_LIVE=1` 后执行 `node scripts/verify-product-android.mjs`，会用设备内 Key 发送专用消息并重启 App。附件测试另见当前实现记录。诊断页的旧 API 脚本 `verify-live-ordinary.mjs` 保留作技术回归。这些脚本不加入默认测试，避免重复调用计费；不读取或输出 Key。

正式页面性能使用 `node scripts/measure-page.mjs --product`（隔离 Edge Lighthouse）与 `node scripts/measure-product-android.mjs`（设置 Android 序列号），应串行测量避免争抢资源。当前普通聊天首屏三次Edge TBT约171–179ms、LCP528–641ms，MuMu LCP681–718ms，CLS均0，达到既有实验参考区间；不代表Remote长会话或真机冷启动性能。包含PDF引擎与字体资源的当前debug APK约11.67MiB，PDF JavaScript按需加载，详见[当前测量及边界](./docs/integration/ordinary-current.md#当前正式入口复测2026-09-27)。
