## 已复现的兼容缺口

### P2：图片预取与官方 Markdown 使用不同语法

[remote-markdown-images.mjs:32](https://github.com/KKUCODES/deepseek-harness-mobile/blob/c5fa95cbee8ed6a8ce55db12d5262acb27d9fa56/src/remote-markdown-images.mjs#L32) 单独使用基础 GFM，缺少官方 `windowsPathDestinations`、`recoverLocalImages`。实际 PR ChatMarkdown 配官方 rc.3 浏览器验证：

- `![x](/work/my photo.png)`：官方识别图片，预取结果为空，没有读取，只显示替代文本。
- `![x](C:\work\_photo.png)`：官方保留路径，预取却读取 `C:\work_photo.png`，无法匹配。
- `![x](/work/a%23b.png)`：预取读取 `/work/a#b.png`，resolve 又截掉解码后的 `#` 后缀，最终没有图片。

建议共用官方解析和文件地址处理，保持两端解码与片段语义一致；补真实 ChatMarkdown 接线回归，不能只测试自建预取器。

### P2：短暂断线被缓存为整个会话期间的永久失败

[138行](https://github.com/KKUCODES/deepseek-harness-mobile/blob/c5fa95cbee8ed6a8ce55db12d5262acb27d9fa56/src/remote-markdown-images.mjs#L138) 跳过已有条目，[179行](https://github.com/KKUCODES/deepseek-harness-mobile/blob/c5fa95cbee8ed6a8ce55db12d5262acb27d9fa56/src/remote-markdown-images.mjs#L179) 把所有读取错误记为失败。模拟首次断线、恢复连接、再次预取同图，读取次数仍为1，结果仍为失败占位。没有显式重试入口或连接恢复重试。

应保留并发和去重，区分网络错误与格式/超限，提供显式重试或受控的连接恢复重试，避免立即无限重试。

### P2：缓存参数恢复丢失未闭合 JSON 中的完整字段

[remote-recent-chat.mjs:15](https://github.com/KKUCODES/deepseek-harness-mobile/blob/c5fa95cbee8ed6a8ce55db12d5262acb27d9fa56/src/remote-recent-chat.mjs#L15) 对流式片段整体 `JSON.parse`，失败返回空字段，再包装为 sealed 视图。以 `{"file_path":"a.txt","extra":"streaming` 为输入，官方 `PartialArguments.fromText` 可读取 `file_path=a.txt`，PR 恢复后 keys 为空、字段 undefined。

运行中离开、回到缓存或中断工具调用可遇到该边界。此项是新增缓存恢复修复不完整，不是声称原 .21 的缓存工具渲染已完善。建议直接恢复官方 PartialArguments，避免维护近似的方法集，并补流式和中断参数回归。

## .21 是否被覆盖

双方修改文件交集只有 `docs/project-knowledge/catalog.md`、`docs/releases.md`。PR 未修改 .21 的四个核心文件：`src/remote-history-position.mjs`、`src/ui/RemoteHistoryList.jsx`、`src/remote-input-session.mjs`、`src/ui/RemoteComposer.jsx`。

因此，将新增改动正常接入当前 rc.3 不会直接撤销旧锚点竞争、列表起点变化和 sending 冻结修复。PR 自身仍为 preview.20/code30；直接以 PR 整树替换当前源码、从 PR 分支构建会遗漏 .21。PR 目标 main 当前也未包含 .21，不能把合到 main 等同于已整合当前发行。

隔离构建以当前 .21 为基础，仅在 esbuild 中覆盖 PR 的产品改动，没有运行 Git 合并，也没有改当前产品文件。当前 rc.3 原 Session 配受控协议回放通过：主/旁栏各24批、各16次向更早滚动；分页等待期6种滚动偏差0；最近会话缓存/重连/草稿偏差0；sending 通知不解锁、不重复提交，失败保草稿可重试。

最早页按钮消失用例有现有不稳定性：首次组合运行锚点差约1930px，随后单次三组对照均通过；再分别重复5次，原 .21 与组合构建均为2次通过、3次失败，原分支约1912px、组合约1930px。不能归责于 PR，也不能称其稳定通过。尚未区分真实定位缺口和脚本/动画测量时序，不代表已找到用户现场的完整根因，继续由 [KKC-129](https://linear.app/kkcodes/issue/KKC-129) 跟踪。
