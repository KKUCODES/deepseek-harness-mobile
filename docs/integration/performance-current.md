# 当前 Remote 页面性能

- 状态：当前 APK 的真实 Remote 首屏、列表就绪与既有聊天打开已测；不代表全部负载或标准 Lighthouse TBT 通过。
- 维护角色：项目协作 Agent；核验日期：2026-10-03。
- 依据：[用户确认的合理区间及可选深测边界](../plugin-validation/validation-plan.md#当前性能验收)、[采集函数](../../scripts/measure-remote-android.mjs)、[三次原始报告](../../artifacts/remote-product-performance.json)。

## 环境与方法

MuMu Android 12，WebView Chrome 110.0.5481.154，调试连接开启，实际 `remote.html`、原日常绑定、本地真实网关与 DSH。三次页面 reload，保留已有缓存、插件与会话数据；等待已连接电脑及测试会话可见，再观察两秒；点击“DSHM Remote 联调提示”，等待16条模型回复和编辑器出现、两次动画帧，再观察两秒。没有发模型消息、改设置或重新配对。

实际安装 APK 的 SHA-256 与当前构建逐字一致：`37b9eaea3218ef5523caf4bd5f038c2fd234cb6230a39ef08ed10fa37dbd11db`。这不是 Activity 冷启动、物理手机、公网网络、模型首字延迟或现场用户 p75 测量。

## 结果

| 指标 | 三次中位数 | 最差 | 含义 |
| --- | --- | --- | --- |
| FCP | 45.3 ms | 45.6 ms | 首次内容绘制，可能仍是连接中页面 |
| LCP（点击前） | 818.5 ms | 821.4 ms | 最大内容绘制，不等于电脑数据就绪 |
| CLS（点击前） | 0.00189 | 0.00189 | 已排除近期用户输入对应偏移 |
| 会话列表可用 | 3280.9 ms | 3679.3 ms | 包含真实认证、插件加载、数据读取和驱动观察延迟；三次范围2800.1–3679.3 ms |
| 点击后聊天可用 | 617.1 ms | 628.3 ms | 包含真实历史读取、渲染和驱动点击等待 |
| 全观察窗最长任务 | 362 ms | 381 ms | 主线程仍有明显长任务，不能称为无卡顿 |
| 全观察窗长任务超50 ms部分合计 | 736 ms | 775 ms | 两个阶段合计，**不是标准 TBT** |

初始阶段最长任务355–381 ms，打开16条既有回复阶段最长325–332 ms。FCP/LCP/CLS落在原绘制参考范围，但列表就绪比首屏晚约2–3秒；不以首屏数字掩盖连接等待。现有证据没有证明这些等待均来自网络，也没有证明某个插件是长任务根因，不据此改认证流程或移除插件。

按用户“合理区间、不必过严”的要求保留这组具体表现与优化余地，不新增严格帧率、5000条压力数据、物理手机或公网为首版门槛。普通聊天的独立Edge/Lighthouse TBT历史报告见[普通聊天性能](./ordinary-current.md)，不能当作当前Remote的标准TBT。若继续优化，以本组固定聊天和加载路径作为前后基线；需要CPU采样才可归因。

## 恢复与采集边界

三次结束仍在原聊天，空草稿保持、errors为空、日常设备active/management=false；采集器及其新文档脚本已删除。没有变更App、DSH、网关、Key或权限。

首次采集未启用CDP Page域，初始化脚本未执行；[失败记录](../../artifacts/remote-product-performance-probe-failed.json)保留。启用Page域后单独验证脚本实际运行，再重新完成三次测量。该问题属于测量驱动，不作为产品缺陷或性能优化。

采集函数接收已有的真实Android Playwright页面，以 `measureRemoteAndroid(page, onProgress)` 调用；它要求当前为固定测试聊天、空草稿且没有生成中任务，不自行启动App、不修改凭据。报告会覆盖当前测量文件，重测前需要保留旧报告。报告中的设备安装哈希和最终授权由本轮外围只读检查补充，函数自身仅记录构建APK哈希，不伪称所有运行环境自动核对。
