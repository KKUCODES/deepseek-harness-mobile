# 停用首页插件后待连接页没有回退：诊断

- 状态：修复前只读诊断记录；后续已完成[通用页面宿主与回退](./remote-connection-plugin-current.md)，下文保留当时排查范围。维护：手机端维护者；核验：2026-10-27；[KKC-122](https://linear.app/kkcodes/issue/KKC-122)。
- 用户反馈停用界面插件后待连接页仍为新版。保留当前未提交UI、图片与思考修复，不修改DSH、不混旧适配分支。

## 代码确认的原因

[RemoteApp](../../src/RemoteApp.jsx)始终直接绘制[RemoteConnectionPage](../../src/ui/RemoteConnectionPage.jsx)，包括未配对、连接中、等待审批、读取中和连接错误。传入的是连接状态与业务回调，没有界面插件状态或页面席位。`stage === ready`仅隐藏连接页，转入Workspace。

界面插件则依赖RemoteModel的组装回调安装插件宿主；[RemoteHomeExtension](../../src/remote-plugin-slots.jsx)只在`dshm.remote.home`处检查运行状态并回退[DefaultRemoteHome](../../src/ui/DefaultRemoteHome.jsx)。[公开API](../plugins/remote-home-api.md)和[插件包](../../packages/remote-home-design/package.json)目前也只声明这个首页槽。此路径确实没有把待连接页交给插件管理。

因此无需假设开关持久化丢失或样式卸载失败，就能解释现象：即使首页插件已停用，固定的新连接页仍继续绘制。停用后只回退已连接首页，无法恢复旧连接界面。`v0.1.0-preview.11`的RemoteApp仍有旧连接页面JSX，可作为默认视图来源，但当前没有相应可选回退接线。

本轮未操控MuMu开关、断开真实连接或录制运行时复现；上述为确定的静态路径缺口，不能冒称已完成真实启停验收。当前安装包及用户数据保持。

## 通用修复方向（未实施）

1. 在不依赖电脑连接成功的本地界面宿主提供连接页席位；本地插件加载和生命周期不能依赖RemoteModel组装。保留一份宿主默认连接视图。
2. 新版连接页与新版首页由同一独立界面包分别注册公开席位；未安装、停用、卸载、加载/呈现失败时，各席位统一回退默认视图。不按包名开关宿主写死的新旧组件。
3. 连接、配对、审批监听、读取/重试、诊断和导航继续归宿主；插件只接收必要的展示投影和限定操作，不能把Key、设备凭据或原生桥暴露为界面props。
4. 补齐尚未连接、连接中、待审批、读取中、失败及已连接首页的启停/卸载/失败回退矩阵，验证跨页面即时生效、原配对/会话/草稿保持。源码来源和兼容范围以实施时实际API核验为准。

仅增加`enabled ? 新连接页 : 旧连接页`会继续把新版UI编入宿主，无法验证独立插件和第三方替换能力，因此不能作为完整的插件边界修复。
