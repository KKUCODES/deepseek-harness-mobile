## 用户行为

普通聊天抽屉的「插件 → 手机」统一管理随App提供的插件，包括普通聊天插件和界面插件。所有条目共用搜索、详情、安装目录、安装/卸载/启停/失败重试；配置组件按目录声明的能力提供，不按插件包名判断。卸载停止插件、从已安装列表移除，之后可在安装目录重新安装；设置、聊天、Key和电脑配对不删除。

这里的安装/卸载管理随包插件的注册状态，不会改写APK内的只读资源。没有实现任意npm包下载、依赖解析或第三方代码安装；先前独立npm适配分支未合入。没有修改DSH、电脑插件或中转服务。

| 状态 | 统一含义 |
| --- | --- |
| 未安装 | 已卸载，仍可在安装目录找到 |
| 等待同步 | 对应宿主尚未迁移旧记录，不能声称已运行 |
| 已停用 | 已安装但用户关闭 |
| 待加载 | 用户已启用，但对应宿主尚未确认激活 |
| 正在加载/停止 | 对应宿主执行生命周期操作中 |
| 运行中 | 宿主实际激活成功，且报告对应当前安装记录版本 |
| 加载失败 | 已启用但实际激活失败，可显式重试；默认界面兜底 |

运行状态由宿主决定，不以电脑联网与否直接判断。已经加载的首页在断线/重连中继续运行；没有可用首页宿主时保持待加载，不把“已启用”冒充运行中。首页停用、卸载、加载或渲染失败时恢复默认首页；会话、项目/搜索和阅读记忆仍在原宿主。

## 统一实现与边界

比较了两类插件各维护一套安装状态、以及共享目录/权威记录/通用执行器两种方案。前者改动较少，但继续存在卸载缺口、双来源存储和状态语义不一致；采用后者，只在真实宿主适配激活方式，不在管理页分支判断插件名称。

- [唯一目录](../../src/phone-plugin-catalog.mjs)：声明id、版本、来源、宿主、可选互斥组、配置能力和模块加载器。互斥组启用另一个条目时停用前一个，不卸载它。没有以某个包名特判运行规则。
- [统一管理与宿主执行器](../../src/phone-plugins.mjs)：相同的安装操作和状态投影；普通聊天通过原Cordis模块/输入服务激活，Remote通过[只负责加载和释放的界面加载器](../../src/mobile-interface-plugins.mjs)激活。加载器不再保存第二份选择。运行报告绑定记录修订与宿主租约，迟到结果和旧宿主释放不能覆盖当前状态。
- [原生权威记录](../../android/app/src/main/java/dev/dshmobile/validation/PhonePluginStore.kt)：Application共享`dshm.phone-plugins.v2`，只持久化安装、启停与版本；运行状态不写磁盘。先成功持久化才广播新意图，写入失败保留原状态。普通聊天和Remote来源不同，不能靠复制localStorage模拟同步。
- [受限消息桥](../../android/app/src/main/java/dev/dshmobile/validation/MobilePluginBridge.kt)：仅自有主框架的精确来源和页面，限制字段、数量和长度；每个页面只能初始化/报告自己的宿主。变更来自受控目录，无任意URL、文件路径或模型凭据操作。
- [统一管理页](../../src/ui/PhonePlugins.jsx)：单一列表/详情/卸载确认流程；[设置组件](../../src/ui/PhonePluginSettings.jsx)按声明的配置能力解析，复用现有提示词和主题设置，未重新创建设置数据。
- 无原生桥的网页预览使用[本来源后端](../../src/phone-plugin-records.mjs)，仅允许管理本宿主；不能声称实现了跨来源同步。自动页面矩阵显式使用隔离协议后端，Android另验真实共享桥。

普通聊天从旧`dshm:ordinary:plugins:v1`迁移安装/停用/卸载；Remote从自身旧localStorage选择及原生`dshm.mobile-plugins.v1`迁移。只初始化缺失记录，新的明确卸载/停用优先于旧选择，App随包版本升级不自动重新安装已卸载插件。旧原生选择接口保留供旧页面资源兼容，新版不再双写两套安装状态。原提示词/主题LocalSettings、聊天、Key与配对存储未迁移或删除。
