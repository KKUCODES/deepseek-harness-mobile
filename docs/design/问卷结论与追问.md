## 逐项追问结论

以下来自一次一个问题的后续确认；布局细节与 Agent 提案在页面草案中另行标注。

1. **打开 App 的第一屏与恢复（已确认）**：普通启动进入空白新聊天页；历史和 Remote 从侧边抽屉进入。App 仅切后台再回来时保留原页面、聊天、草稿和阅读位置；完全关闭后重新启动默认进入空白新聊天，不删除已有聊天及持久草稿。此前已确定的点击通知进入对应任务规则保留，区别于普通启动；Remote 切回普通聊天的路径另行确认。
2. **返回行为（已确认）**：键盘、侧边菜单或底部窗口打开时返回先收起；都关闭后普通聊天根页返回才退后台。Remote 则逐层返回：远程聊天 → 任务列表 → 普通聊天。
3. **通知（已按用户授权形成设计）**：后续聊天允许运行时发送通知并由 Agent 权衡，采用下方前台/后台分流规则，替代原问卷 21 的仅 App 内提示答案。尚未实现。
4. **终端输入（已确认不需要）**：用户明确“不需要手机输入命令”。手机只查看命令、状态、摘要、工作区目录、时长和输出，使用底部可放大窗口，不提供手动输入/发送命令入口。原首版终端输入目标据此移出范围，不影响通过聊天向 DSH 交代任务或处理审批。
5. **代码下载内容（已确认）**：用户要求下载完整最新文件。右上角按钮获取电脑端该文件当前最新的完整内容，不下载差异记录，也不默认导出这条修改记录对应的历史版本。差异颜色与语法高亮继续用于窗口内查看；文件已删除或读取失败时明确提示，不偷偷替换为旧内容。普通文档/PDF等预览可在低保真方案阶段继续设计。

## 后续确认

- 启动首屏：用户选择空白新聊天页，历史与 Remote 从侧边抽屉进入。
- 普通聊天返回：用户确认先收起键盘/菜单/底部窗口，都关闭后才退后台。
- 通知：用户补充“如果 APP 在运行，则可以发送通知。你权衡一下”，授权按下列规则设计。
- 终端：用户确认手机不输入命令，只读查看执行详情。
- 下载：用户确认下载完整最新文件，对比在窗口内展示。
- 恢复：用户确认后台回来保留原聊天、草稿与阅读位置，完全关闭后重新启动默认空白新聊天。
- Remote 返回：用户选择逐层返回，远程聊天 → 任务列表 → 普通聊天；键盘/菜单/底部窗口先收起。本轮关键追问已完成，未定的布局细节在草案/原型中审阅。

## 通知设计（用户授权 Agent 权衡，待实现）

| 场景 | 行为 |
| --- | --- |
| App 正在前台，用户就在相关聊天中 | 直接更新任务/消息状态，不再发送同事件的系统通知或重复横幅 |
| App 正在前台，事件来自其他任务 | 显示不打断操作的提示条，点击进入对应任务；审批/问题同时进入待处理列表 |
| App 在后台，进程存活且连接可用 | 对 Remote 的需要批准/回答问题、任务完成、执行失败发送系统通知；不保证后台持续联网 |
| App 进程被结束 | 不推送、不唤醒或自动拉起；再次打开尝试重连，读取最新状态，不补发全部历史通知 |

- 默认不对每个输出片段、普通聊天完成或短暂断线发送系统通知；这些状态在 App 内显示，避免频繁打扰。
- 系统通知沿用问卷 22 的偏好：标题与少量摘要，不直接展示长篇输出、完整命令或文件内容；服从系统锁屏隐藏内容设置。
- 点击通知打开对应电脑任务；仅跳转，不直接批准/执行。若状态已变化，展示最新状态；无网络或授权失效时给出恢复入口，不展示已可操作的假状态。
- 同一事件不因前后台切换、重连或重复投递反复通知；按同一待处理事项更新通知，一端完成审批后清理失效提醒。
- 通知权限未授予时继续正常使用 App，仅保留 App 内提示；不把授权作为配对/聊天前置条件。通知设置可开关上述 Remote 提醒类型。
- 这是交互决策，不是已验证后台通知能力；现有“进程结束后不通知、重开重连”要求保持不变。
